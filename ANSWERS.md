# ANSWERS.md

### 1. Почему heroesCreated должно быть статическим?
Потому что это счётчик всех созданных героев в игре. Он относится не к одному объекту, а ко всему классу Hero.

### 2. Почему name, health и level не должны быть статическими?
Потому что у каждого героя свои уникальные имя, здоровье и уровень. Если бы они были статическими — все герои имели бы одинаковые значения.

### 3. Почему printHeroesCreated() можно вызвать без создания объекта?
Потому что метод статический (`static`). Статические методы принадлежат классу, а не объекту.

### 4. Можно ли из статического метода напрямую обратиться к нестатическому полю name? Почему?
Нет, нельзя. Статический метод существует без создания объекта, а поле `name` существует только внутри объекта. Компилятор выдаст ошибку.

### 5. Почему проект перестанет компилироваться если пометить класс Hero модификатором final?
Потому что от финального класса нельзя наследоваться. А у нас есть классы Knight, Archer, Mage, которые наследуются от Hero.

### 6. Почему переменные имеют тип Hero, но вызываются версии метода attack() из конкретных наследников?
Это **полиморфизм**. В runtime Java определяет реальный тип объекта (Knight/Archer/Mage) и вызывает переопределённый метод.

### 7. Почему переменная knight имеет модификатор final, но её поля могут быть изменены?
`final` на переменной запрещает менять **ссылку** (нельзя присвоить новый объект). Но содержимое объекта (поля) можно менять, если они не `final`.
